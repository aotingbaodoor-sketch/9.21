## 11组实际通过的验收

1. 空库没有默认用户；实际执行管理员初始化命令，二次初始化拒绝覆盖。
2. 管理员创建员工A/B、分配客户，两人独立登录只看到各自数据。
3. 销售A猜测B客户ID，详情/编辑/新增跟进返回404；管理员接口返回403。搜索、统计、通知、记录和导出不泄露B客户。B已有真实跟进记录时，A历史和导出仍为空；通知已读状态按查看者独立保存。
4. A级自动下一次为业务日期+1天；修改周期后按新周期计算；手工日期优先。今日、逾期、完成状态正确，同一幂等键重试只有一条跟进记录。
5. 两个旧/新版本编辑冲突返回409且保留新值；软删除后不可见，恢复后3条原客户跟进记录仍保留。
6. 来源/CSRF拒绝、员工重置密码、停用后旧会话失效、会话过期拒绝访问。
7. 旧数据负责人映射、库内和文件内重复预检、已导入保护、标签筛选和分页。
8. 退出重登、独立会话读取一致；实际关闭再启动 API 服务与 PostgreSQL 进程，数据、历史和可用会话保留。
9. 一致性备份实际恢复到另一空数据库，核对客户、4条跟进及3个账号；不恢复会话；非空库和损坏文件拒绝恢复。
10. 实际执行备份 CLI、恢复 CLI 到第三个独立数据库，核对客户与历史数量。
11. 桌面1440×1000、手机390×844：管理员从页面创建员工、搜索客户、查看历史；销售从手机界面登录、新增客户、搜索、刷新、填写反馈/计划并保存跟进、退出重登；越权URL与浏览器API均拒绝，另一个B浏览器上下文不见A客户。测试流程没有JavaScript异常、意外控制台错误或手机页面横向溢出。
