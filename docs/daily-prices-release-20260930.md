# 每日价格与运费：实施与上线核验

## 本次范围

在现有 React / Express / PostgreSQL / Railway 服务增量增加 `/daily-prices`。
不是整包CRM交付完成证明。现有QT、定金、SO/PO、生产门禁与WhatsApp方案保持。

| 要求 | 实际实现 / 限制 |
| --- | --- |
| 员工中文查询 | 汇率、物流、产品三类表格，搜索、状态、路线、运输方式、柜型、体积、重量和出运日期筛选 |
| 真实汇率 | ECB官方XML，原始文本和不可覆盖的版本留存，按CNY/外币交叉换算；不是银行现汇买入/卖出报价 |
| 日期 | 来源只提供日期，保留原日期，不虚构时刻；检查、首次同步该版本分别记录 |
| 公司汇率 | 默认保留既有人工核准规则。管理员可明确采用ECB参考值并设置缓冲；无授权不替换 |
| 自动任务 | 原Railway常驻服务每分钟检查DB到期任务；默认北京07:30、23:30。DB租约/过期恢复、3次网络重试、15分钟失败补试 |
| 失败提示 | 保留最后成功数据、显示原有效期/同步失败；管理页面和顶部同步异常提醒 |
| 货代/工厂接入 | 当前生产没有产品/货代价格，也无对应API配置。实现CSV/XLSX人工导入、原文件存档、待核对、管理员批准/驳回；不能宣称这些来源自动接通 |
| 产品销售与成本 | 员工接口仅允许销售字段；原始文件只向管理员开放。销售不能取得工厂底价、内部价、最低价或利润 |
| 运费权限 | 保留现有运费成本查看授权；未获授权时隐藏采购运价，销售总运费在正式报价计算中查看 |
| 供应商变价 | 所有导入先待核对，不自动覆盖。核准导入保留既有其他销售规则；复杂规格、组合公式和包装重量仍在管理员高级设置维护 |
| 报价关联 | 原产品/运价选择器使用核准目录，计算使用公司有效汇率；快照保存版本依据。草稿变价必须另存并审核，禁止静默改金额 |
| 已签发单据 | 继续使用数据库不可修改的input/snapshot和已生成PDF字节；日常同步不改QT编号或历史内容 |
| 缺项 | 必需价格/汇率/费用缺失时总价为空并列出硬错误，不能签发完整假报价 |

## 数据源

- XML：https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml
- 来源说明：https://data.ecb.europa.eu/key-figures/ecb-interest-rates-and-exchange-rates/exchange-rates
- ECB统计复用政策：https://www.ecb.europa.eu/stats/ecb_statistics/governance_and_quality_framework/html/usage_policy.pl.html
- 原始基准1 EUR，人民币参考值=每EUR的CNY/每EUR的相应外币；JPY显示每1日元，不是每100日元。
- 不把网络指数当可出运货代报价。不对未覆盖币种猜测或用美元锚定补值。

## 上线验证方法

`node --import tsx scripts/pricing-production-check.ts <Railway CLI> <部署提交SHA> <仓库外证据目录>`

该脚本核对实际health版本，用短期隔离测试管理员/销售账号登录真实HTTPS站点，执行云端同步，对照官方XML逐项验证API数值及页面USD显示，检查无新数据、权限、调度时间、既有报价/PDF哈希及桌面/手机操作。不会更改真实客户付款、不会发WhatsApp通知、不会往生产价格库灌入演示价格；结束后停用测试账号及删除测试会话。真实故障/过期场景在隔离测试验证，不故意破坏生产来源。

## 还需业务资料

1. 工厂/公司核准价目表：型号、完整规格/尺寸/五金/玻璃/颜色/包装、计价单位、销售价格、真实提供方、发布时间、生效及截止日期；采购成本只给管理员资料。
2. 货代资料：供应方、授权API/平台或原始Excel/CSV；航线/柜型/重量体积范围、出运有效期、币种、逐项主运费/附加费/港杂费、收费单位与最低收费、包含/不包含项目。未知金额留空。
3. 公司外币报价政策：是否正式采用参考汇率及缓冲。界面提供明确确认操作；不自动用参考值冒充银行成交价。

新增付费数据源、货代账号授权和真实报价资料尚未提供；没有购买任何新套餐。
